# LLM Wiki 模式 — Karpathy 的持久化知识库方案

> 原文：[LLM Wiki by Andrej Karpathy](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

## 核心主张

传统 RAG 每次查询都从原始文档重新检索拼装，没有积累。LLM Wiki 的核心区别是让 LLM **增量构建并维护一个持久化的 wiki**——知识被编译一次然后持续更新，而非每次重新推导。

> "The wiki is a persistent, compounding artifact. The cross-references are already there. The contradictions have already been flagged. The synthesis already reflects everything you've read."

## 三层架构

| 层 | 内容 | 所有者 | 性质 |
|---|------|--------|------|
| Raw Sources | 原始文档（文章、论文、图片、数据） | 人类策展 | 不可变 |
| Wiki | LLM 生成的 markdown 文件集合 | LLM 完全拥有 | 持续演进 |
| Schema | 配置文件，定义结构/约定/工作流（如 CLAUDE.md） | 人机共同演进 | 元配置 |

## 三个核心操作

### Ingest（摄入）

添加新源 → LLM 阅读 → 写摘要页 → 更新索引 → 更新相关实体/概念页 → 追加日志。一个源可能触及 10-15 个 wiki 页面。

### Query（查询）

问问题 → LLM 先读 index 定位 → 搜索 wiki 页面 → 综合答案 + 引用。关键：**好的答案可以存回 wiki**，让探索也产生复利。

### Lint（健康检查）

定期审查：矛盾、过期信息、孤儿页面、缺失交叉引用、数据空白。LLM 可建议新问题和新源文档。

## 导航机制

- **index.md**（内容导向）：所有页面目录 + 单行摘要 + 分类。~100 源 / 数百页规模下足够用，无需 embedding。
- **log.md**（时间导向）：append-only 操作日志，格式化前缀可被 unix 工具解析。

## 为什么有效

> "维护知识库的乏味部分不是阅读或思考——是记账。人类放弃 wiki 是因为维护负担增长速度超过了价值。LLM 不厌倦，不忘记更新引用，一次操作能改 15 个文件。"

- **人的工作**：策展源文档、指导分析方向、问好问题、思考意义
- **LLM 的工作**：总结、交叉引用、归档、记账——所有 grunt work

## 适用场景

| 场景 | 说明 |
|------|------|
| 个人成长 | 目标/健康/心理追踪，日记/文章/播客笔记归档 |
| 研究 | 数周/数月深入一个主题，论文/报告增量构建 |
| 读书 | 逐章归档，建立角色/主题/情节线页面（类似 fan wiki） |
| 团队知识库 | Slack/会议/项目文档自动维护，解决"没人愿意更新 wiki"的问题 |
| 竞品分析/尽调/旅行规划/课程笔记 | 任何需要长期积累并组织知识的场景 |

## 与 Claude Code 架构的映射

| LLM Wiki 概念 | Claude Code 对应 |
|---|---|
| Wiki = 编译后的知识（非每次重新推导） | Session Memory — 提取记忆持久化 |
| index.md = 导航入口 | MEMORY.md = 记忆索引 |
| Schema = LLM 行为约定 | CLAUDE.md = 项目指令 |
| Lint = 一致性检查 | Verification Agent = 正确性检查 |
| Raw Sources 不可变 | tool_result 不可变（事实源） |
| Query 结果可存回 wiki | 对话中的洞察可存为 memory |

## 与 Vannevar Bush's Memex (1945) 的关系

> "Bush's vision was closer to this than to what the web became: private, actively curated, with the connections between documents as valuable as the documents themselves. The part he couldn't solve was who does the maintenance. The LLM handles that."

## 设计原则提炼

1. **编译优于检索** — 知识应该被预处理为结构化形式，而非每次从原始态推导
2. **复利效应** — 每次操作（ingest/query/lint）都让 wiki 变得更丰富
3. **人机分工明确** — 人做策展和思考，LLM 做所有机械性的记账工作
4. **源文档不可变** — 事实来源与 LLM 生成的综合严格分离
5. **Schema 驱动** — 配置文件定义行为约定，而非靠隐式习惯
6. **渐进式复杂度** — 从 index.md 开始，规模增长后才引入搜索引擎
