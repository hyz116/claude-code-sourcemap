# Wiki Schema

本文件定义 docs/ 作为 LLM Wiki 的结构约定、页面格式和工作流。LLM 在操作本 wiki 时应遵循以下规范。

## 定位

这是一个围绕 Claude Code 源码的**持续演进知识库**，目标是：
1. 深入理解 Agent 架构的设计哲学和工程实践
2. 提炼可迁移到其他 Agent 系统（如 leto-ai）的设计模式
3. 追踪对 Agent 领域的认知演进

## 目录结构

```
docs/
├── SCHEMA.md              ← 本文件（wiki 行为约定）
├── index.md               ← 全局索引（按类型分区，带一行摘要）
├── log.md                 ← 操作日志（append-only）
│
├── [0-7].*.md             ← 模块综合分析（种子文档，可继续更新）
│
├── insights/              ← 高维综合（设计哲学、跨模块洞察、外部参考）
│   ├── README.md
│   └── *.md
│
├── concepts/              ← 概念页（一个设计模式/机制一页）
│   └── *.md
│
├── entities/              ← 实体页（一个关键文件/类/模块一页）
│   └── *.md
│
└── comparisons/           ← 对比页（两种设计的优劣对比）
    └── *.md
```

## 页面格式

### 概念页（concepts/）

```markdown
# {概念名}

> 一句话定义

## 核心机制

（机制描述，含源码引用）

## 在 Claude Code 中的体现

（具体文件和行号）

## 设计原则

（为什么这样设计）

## 关联

- 相关概念：[[concept-name]]
- 相关实体：[[entity-name]]
- 综合分析：[[module-doc]]
```

### 实体页（entities/）

```markdown
# {文件名/类名}

> 源码位置：`restored-src/src/path/to/file.ts`

## 职责

（一段话说明这个文件/类做什么）

## 关键设计

（核心逻辑、重要的设计决策）

## 与其他实体的关系

（调用关系、依赖关系）

## 关联概念

- [[concept-name]]
```

### 对比页（comparisons/）

```markdown
# {A} vs {B}

> 对比背景（为什么需要对比）

## 对比维度

| 维度 | A | B |
|------|---|---|
| ... | ... | ... |

## 适用场景

## 结论
```

## 命名规范

- 文件名用 kebab-case：`circuit-breaker.md`、`query-ts.md`
- 链接用双括号语法：`[[circuit-breaker]]`（兼容 Obsidian）
- 源码引用格式：`file.ts:123` 或 `file.ts:123-456`

## 交叉引用规则

1. 每个页面底部必须有 `## 关联` 部分
2. 新建页面时检查 index.md 是否有相关已有页面，主动添加双向链接
3. 修改现有页面时检查是否需要更新相关页面的引用

## 工作流

### Ingest（摄入新源码分析）

1. 阅读源码/讨论新模块
2. 判断产出应归为哪类页面（概念/实体/对比/综合）
3. 创建或更新对应页面
4. 更新 index.md
5. 检查并更新相关页面的交叉引用
6. 追加 log.md

### Query（查询）

1. 先读 index.md 定位相关页面
2. 读取相关页面综合回答
3. 如果答案有独立价值 → 存为新页面或更新现有页面

### Lint（健康检查）

定期检查：
- 孤儿页面（无入链接）
- 概念被提及但没有独立页面
- 页面间矛盾（新发现推翻旧结论时）
- index.md 是否与实际文件同步

## 演进原则

1. **增量优于重写** — 新发现追加到现有页面，而非推倒重来
2. **小页面优于大文件** — 一个概念一页，方便链接和复用
3. **链接即结构** — 页面之间的链接关系就是知识的结构
4. **标记过时** — 发现旧内容不再准确时，在原文加 `> [!warning] 已过时：...` 而非删除
5. **种子文档保留** — 0-7 号文件是 wiki 的种子，可更新但不拆散
